# 该订多少 · 小店订货决策台

管理信息系统课程项目（2 人组）。核心问题：**一家小店该订多少？**

## 跑起来

```powershell
python scripts/make_demo_data.py   # 生成 84 天仿真流水（20 个 SKU）
python scripts/build_db.py         # 建库灌数
streamlit run app.py               # 打开 http://localhost:8501
```

账号：`boss / 123456`（店主）、`clerk / 123456`（店员，看不到进价与毛利）。

## 页面

| 页面 | 作用 |
|---|---|
| 首页 | 四个指标一屏：缺货率、报损率、缺货损失、缺货/报损倍数 |
| 收银台 | 开单扣库存；一键标记售罄（项目的数据来源） |
| 进货入库 | 录入到货，库存增加 |
| 决策台 | 拖滑块 → 报童公式 → 建议订货量；反事实重放“那天多订 5 件” |
| 诊断 | 哪个品类常年多订、哪个常年少订 |
| 后台 | 角色、决策日志、数据规模 |

## 数据说明

`make_demo_data.py` 生成的是**参数化仿真数据**，没有任何一条来自真实门店。

- 真实的部分：报童模型公式、需求截断的机制、品类与保质期的逻辑关系。
- 编的部分：每一个销量、每一次售罄时刻、每一张进货单。
- 参数（进价 3.1 / 售价 9.0 / 残值 2.4 / μ 13 / σ 4）：**是为了让演示成立而选取的假设值，
  量级参考常见零售区间，但没有逐项核对出处。答辩前必须二选一：换成可引用的来源，
  或在 PPT 上明确写“假设值”。**

订货策略固定为“上周同星期卖多少订多少 +8%”，用来复现小店的典型行为。
随机种子固定（42），任何人重跑都会得到同一份数据。

### 截断实验（答辩最硬的一张图）

```
python scripts/backtest_truncation.py
```

把日销量按小时铺开、模拟“订少了中途售罄”，再比较两种需求估计：

| 方法 | 平均绝对误差 | 系统偏差 |
|---|---|---|
| 只看销量（多数 POS 的做法） | 6.8% | −6.6%（系统性低估） |
| 售罄补齐 | 1.6% | 0.0% |

输出 `data/truncation.svg`（可直接放进 PPT）和 `truncation_result.csv`。

**真数据版**：把 UCI Online Retail 的 `online+retail.zip` 放到 `data/`，
先跑 `python scripts/from_uci.py` 生成 `data/uci_daily.csv`，
再跑 `backtest_truncation.py`，就会用真实流水替换掉合成序列。
（本机下载时服务器在 300KB 处断开，未跑通，需在正常网络下重试。）

**这个实验的局限**：日内分布是假设的，所以“误差降到 1.6%”有循环论证成分。
它能证明**方向对**（截断会系统性低估、补齐能纠正），不能证明**幅度**。
真值要靠三天实地观察补。
