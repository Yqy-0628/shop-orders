# 运行说明

本文档让人在不看代码的前提下把系统跑起来、接入一家真实门店、并复现答辩时的演示。

---

## 1 环境

| 项 | 要求 | 说明 |
|---|---|---|
| Python | 3.11 或 3.12 | 3.13 以上部分依赖没有预编译包 |
| 依赖 | `requirements.txt` | streamlit、pandas、numpy、pillow、qrcode、python-barcode、python-docx |
| 数据库 | SQLite（Python 内置） | 无需另外安装服务 |
| 操作系统 | Windows / macOS / Linux | 启动脚本为 Windows 批处理，其他系统用命令行 |

安装依赖：

```powershell
cd shop-orders
python -m pip install -r requirements.txt
```

---

## 2 启动

Windows 双击 `启动.bat`。脚本会检查依赖、缺少数据库时自动重建，然后打开浏览器。

命令行方式：

```powershell
python -m streamlit run app.py --server.port 8501
```

访问 `http://localhost:8501`。

| 账号 | 密码 | 角色 |
|---|---|---|
| `boss` | `123456` | 店长：可改档案、改口令、看进价与毛利、下单 |
| `clerk` | `123456` | 店员：只做收银与台账登记，看不到进价、不能下单 |

角色差异在代码层生效（`core/api.py` 的 `sku_rows` 按角色裁字段），不是只藏界面按钮。

---

## 3 数据库

`data/shop.db` 随仓库提交，含 20 款商品、85 天流水（1,684 个单品日）。拿到仓库即可演示，不必重建。

从零重建：

```powershell
python scripts/make_demo_data.py   # 生成 data/sku.csv、sales.csv、stock_move.csv、stockout.csv
python scripts/build_db.py         # 按 data/schema.sql 建七张表并灌入
```

表结构见 `data/schema.sql`：`sku`、`sales`、`stockout_mark`、`stock_move`、`decision_log`、`app_user`、`label_print`。

两处口径：

- **统计只认种子窗口**（`core/metrics.py` 的 `SEED_END = 2026-11-08`）。演示当天写入的销售与售罄不参与 KPI 与复盘，避免把演示数据算进结论。
- **业务日**取最近一次「已到货入库」的日期（`metrics.biz_day()`），不再硬编码。需要固定时设环境变量 `SHOP_BIZ_DAY=YYYY-MM-DD`。

---

## 4 接入一家真实门店

按三步走，顺序不能颠倒：先有档案，再有流水，最后才是每天的进货与报损。

### 4.1 商品档案（导入页 → 商品档案）

下载模板，表头固定 11 列，顺序不影响识别：

```
编号,品名,分类,规格,来源,进价,售价,处理价,保质期,条码,供货商
```

| 列 | 必填 | 规则 |
|---|---|---|
| 编号 | 是 | 门店自定，文件内不可重复；已存在的编号执行更新 |
| 品名 | 是 | |
| 分类 | 是 | 面包、饮品、饼干等，用于标签页分组与看板汇总 |
| 规格 | 否 | 口味、克重等细分描述 |
| 来源 | 否 | 写「自制」或「进货」；留空则面包、饮品视为自制，其余视为进货 |
| 进价、售价 | 是 | 售价必须高于进价 |
| 处理价 | 否 | 报废折价，留空按 0，须低于进价 |
| 保质期 | 是 | 1 至 7 天，整数 |
| 条码 | 否 | 留空按分类自动编号（`SH1xx` 日配、`SH2xx` 烘焙、`SH3xx` 饮品、`SH4xx` 鲜食） |
| 供货商 | 否 | 进货类填写，订货单按供货商分家导出 |

「来源」决定一款商品进订货单还是进后厨排产单，是自制与进货并存业态的关键字段。

### 4.2 销售流水（导入页 → 销售流水）

表头固定 5 列：

```
日期,单品,数量,单价,时段
```

- 日期：`2026-11-20`、`2026/11/20`、`20261120` 均可，带时分秒会截掉
- 单品：编号、条码、品名三种写法任选，系统按唯一命中识别
- 数量：正整数
- 单价：留空按商品档案售价
- 时段：0–23 的整点小时，非必填；缺省按 14 点计

同一份文件导第二遍会重复累计。需要重导时勾选「先清空这段时间的旧记录」并指定区间。

### 4.3 每天的进货与报损（收银页 → 台账登记）

系统不从销售流水倒推进货。每天的动作是：

1. 订货页选定档位 → 生成次日「在途」进货单
2. 次日到货，在「台账登记 → 到货登记」选中该在途单，按实收数量确认
3. 打烊前登记报损、标记售罄

只导销售、不记进货时，今日页会提示「当天没有进货登记」，余额不作判定，不会显示成一排账实不符。

## 5 自检与演示

```powershell
python -m unittest discover -s tests        # 27 例：核心逻辑 + 八个页面 × 两种角色
python scripts/verify_import_flow.py        # 空库导入端到端：档案 20 款 + 28 天流水 → 预测与建议可用
python scripts/demo_flow.py --day 2026-11-10  # 全链路演练：订货 → 到货 → 结账 → 售罄 → 报损 → 收工账
```

`demo_flow.py` 在一个临时业务日里跑完整条链路，跑完自动撤回当天流水，只留下订货决策与在途单，业务日回到原值，复盘数字不变。用于答辩前确认链路无断点。

## 7 常见报错

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: streamlit` | 依赖没装 | `python -m pip install -r requirements.txt` |
| `no such table: sku` | 数据库缺失 | `python scripts/build_db.py` |
| 导入校验整列报错、提示缺列 | 表头被改动 | 用页面上的模板重填，表头保持固定 |
| 到货登记看不到在途单 | 当天没有下单，或已确认过 | 订货页选定档位后会生成次日 在途 单 |
| 今日页四个指标全为 0 | 业务日没有流水 | 确认 `data/shop.db` 存在；或设 `SHOP_BIZ_DAY` 指定日期 |
| 二维码扫不开 | 地址有误或服务休眠 | 重新生成二维码，先手动访问唤醒 |
| `PermissionError` 写库失败 | 云端只读文件系统 | 本地运行；云端用临时副本模式 `SHOP_DB_MODE=temp` |
